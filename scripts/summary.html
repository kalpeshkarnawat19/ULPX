ULPF-X: Architectural Summary & Technical Specification

Document: summary.md
Problem Statement: SIH26156 — National Technical Research Organisation (NTRO)
Topic: Log Parameters, Decision Logic (What to Keep), Input Ingestion, and Output Formats

1. Executive Summary: What is ULPF-X?

Traditional log pre-processing pipelines (Logstash, Vector, Fluentbit) focus simply on parsing strings into JSON. However, in high-security and intelligence environments (NTRO, defense, enterprise SOCs), traditional pipelines introduce severe risks:
1. They silently drop raw evidence when parsing errors occur.
2. They hallucinate or guess mappings for ambiguous fields.
3. They alter security semantics, causing threat detection rules to fail silently.
4. They lack cryptographic forensic lineage, making normalized logs inadmissible in incident response or legal audits.

ULPF-X (Universal Log Pre-processing Framework) solves this by acting as a continuously verified security-telemetry trust layer. It guarantees 100% raw byte preservation, zero dynamic code execution, mathematical detection preservation (DPS), and automated self-healing against format drift.

2. What Parameters / Fields Are Considered?

ULPF-X normalizes incoming heterogeneous security telemetry into a schema-neutral Canonical Intermediate Representation (ULPF-IR) covering 14 structured field families, plus raw forensic provenance and unknown vendor extensions:

The 14 Canonical Field Families:

timestamp Universal temporal anchor Normalized ISO-8601 / RFC3339 UTC timestamp, event duration.
event Action and lifecycle event.category, event.action (allowed, blocked, quarantined), event.outcome (success, failure), event.severity, event.dataset.
source Initiator / Client endpoint source.ip (IPv4/IPv6), source.port, source.mac, source.domain, source.user, source.geo.country, source.bytes, source.packets.
destination Target / Server endpoint destination.ip, destination.port, destination.mac, destination.domain, destination.geo.country, destination.bytes, destination.packets.

Forensic Lineage & Metadata Parameters:

  • event_id: Universally unique cryptographic UUIDv4 identifier.
  • source_id: Originating device or collector identifier (e.g. paloalto-fw-01, crowdstrike-edr).
  • raw_ref: Immutable storage URI pointing to verbatim raw bytes.
  • raw_hash: SHA-256 cryptographic digest of the exact raw event string.
  • byte_length: Total raw byte size before parsing.
  • ingest_timestamp: Microsecond-accurate timestamp when the packet hit the ingest gateway.

3. How Do We Decide What to Keep vs. What Not to Keep?

The Cardinal Rule: WE KEEP 100% OF EVERYTHING

In ULPF-X, no log data is ever silently dropped, deleted, or discarded.

                                   │
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
       [Deterministic Telemetry Firewall]   [Immutable Storage Store]
                    │                             │
            ┌───────┴───────┐              (100% Raw Bytes Saved:
            ▼               ▼               URI + SHA-256 Digest)
         Clean         Malformed/Exploit
           │                │
           │         [Quarantine Sink]
           │         (Zero worker crash,
           │          stored for forensics)
           ▼
     [Parser DSL Runtime]
           │
           ├─► High-Confidence Fields (>= 0.95) ──► Canonical IR (14 families)
           ├─► Review Fields (0.80 - 0.95)      ──► Escalate for Human Sign-off
           └─► Ambiguous / Unknown (< 0.80)     ──► unknown_fields (Preserved!)

1. Decision Logic for Field Normalization (The Abstention Principle - Rule 4)

When a log field is extracted, ULPF-X computes an empirical confidence score based on alias matching, type validation, and syntactic context:
- Score $\ge 0.95$ (Auto-Accept): Mapped into the standardized Canonical IR family (e.g. srcip $\to$ source.ip).
- Score $0.80 - 0.95$ (Human Review): Propose mapping in candidate spec; escalate to SOC administrator for sign-off.
- Score $< 0.80$ (Strict Abstention): ULPF-X strictly refuses to guess or hallucinate. The field is untouched and preserved verbatim inside unknown_fields (e.g. unknown_fields.x_vendor_custom_tag = "xyz").
- Result: Unknown field retention is strictly 100.00%.

2. Decision Logic for Ingestion (Telemetry Firewall - Stage 2)

What happens to malformed or malicious logs?
- Accepted Traffic: Payloads adhering to standard structural limits pass directly to the parser hotpath.
- Quarantined Traffic: If a log attempts a Denial-of-Service or exploit:
- Payload exceeds size boundary ($> 1\text{ MB}$).
- JSON nesting depth exceeds safety threshold ($> 16$ levels, preventing stack exhaustion).
- Key length exceeds limit ($> 256$ bytes).
- Invalid UTF-8 or hostile byte sequences.
- What is kept? The firewall quarantines the payload into an isolated investigation sink. It does NOT throw the bytes away; the exact raw bytes and SHA-256 hash are immutably persisted so security analysts can inspect the attack vector.

4. Input: Taken From Where and How?

Where is Input Taken From?

ULPF-X ingests from any security perimeter or host telemetry source across all enterprise formats:
1. Firewalls & Network Gateways: Palo Alto PAN-OS, Fortinet FortiGate, CheckPoint, Cisco ASA.
2. Endpoint Detection & Response (EDR): CrowdStrike Falcon, SentinelOne, Microsoft Defender.
3. Web & Proxies: Nginx, Apache HTTP, Cloudflare, ModSecurity WAF.
4. Cloud Infrastructure: AWS CloudTrail, Microsoft Entra ID / Azure Audit, Google Cloud VPC flow logs.
5. Authentication & Directory: Okta, Active Directory, Linux PAM/SSHD.

Supported Input Formats:

  • Syslog RFC 5424 (<134>1 2026-09-20T12:00:00Z fw-01 ...)
  • Syslog RFC 3164 (BSD Syslog) (Oct 15 12:30:45 core-gw kernel: ...)
  • CEF (Common Event Format) (CEF:0|PaloAlto|PAN-OS|10.1|...)
  • LEEF 1.0 & 2.0 (Log Event Extended Format) (LEEF:2.0|IBM|QRadar|...)
  • Key-Value Pairs (src=10.0.0.1 dst=192.168.1.1 action=deny)
  • JSON / NDJSON (Newline Delimited JSON) (CloudTrail, Okta, Kubernetes)
  • Delimited CSV / TSV (Proxy access logs, database query dumps)

How is Input Taken? (Ingestion Architecture)

  1. Network Listeners (Go Hotpath):
    - High-throughput UDP & TCP socket listeners (Syslog port 514 / 1514).
    - HTTP/REST Ingestion Gateway: POST /api/v1/ingest/raw supporting batch arrays and single streams.
  2. Immutable Capture Layer:
    - The gateway receives the raw byte slice from the TCP/HTTP buffer.
    - It immediately computes SHA-256(raw_bytes) and byte length.
    - It writes the bytes to immutable local storage or object store (MinIO/S3), generating a permanent URI reference (raw_ref).
  3. Envelope Generation:
    - The gateway wraps the event into a versioned RawEventEnvelope (contract v1.0) and publishes it to the internal event bus.

5. Output: File Formats and How They Are Generated

ULPF-X does not lock data into a single vendor format. It produces deterministic JSON artifacts conforming to versioned schemas:

1. Primary Output: Canonical Intermediate Representation (NormalizedEvent)

  • Format: JSON / JSON-Lines (.json or .jsonl).
  • Governing Contract: packages/contracts/normalized_event.schema.json (Draft 2020-12).
  • Structure: Contains the 14 structured field families, raw provenance pointers, and unknown_fields.
  • Purpose: Decoupled neutral ground truth used by internal analytics, alerting, and forensic query engines.

2. Lineage Artifact: Forensic Byte Lineage (FieldLineage)

  • Format: JSON / JSON-Lines.
  • Governing Contract: packages/contracts/field_lineage.schema.json.
  • Structure: For every canonical field, stores:
  • canonical_field: e.g. source.ip
  • raw_pointer: exact byte offset slice [25:37] or JSON pointer /srcip
  • raw_value: verbatim characters from the original string
  • transformation_steps: mathematical and type cast sequence
  • Purpose: Cryptographic provenance proof for courtrooms, audits, and incident post-mortems.

3. Industry Exporter Projections: Pure Projections (Zero Side-Effects)

Without modifying the Canonical IR or losing provenance, ULPF-X deterministically projects events into external industry standards:
- Elastic Common Schema (ECS v8.x): For Splunk, Elastic, and Logstash ingestion.
- Open Cybersecurity Schema Framework (OCSF v1.1): For AWS Security Lake, Snowflake, and modern cloud SIEMs.

4. Continuous Assurance Reports (Audit Records)

  • telemetry_passport.schema.json: Official machine-readable certification badge containing measured extraction accuracy, semantic accuracy, and DPS score.
  • drift_report.schema.json: Statistical drift analysis (Jaccard distance, type mutation, enum inversions).
  • shadow_comparison.schema.json: Side-by-side active vs candidate parser diffs with zero downstream bus leakage.
  • benchmark_report.schema.json: Measured throughput (EPS), latency percentiles (p50, p90, p99), and host hardware specifications.
